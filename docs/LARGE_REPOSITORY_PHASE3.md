# Large archive scan: phase 3

UCE scans public GitHub ZIPs locally in an analysis worker. GitHub archive downloads can be written to private browser storage, or to a file selected by the user when the browser supports the File System Access picker. No uploaded source is sent to UCE for analysis; GitHub downloads use the same-origin relay. A selected ZIP stays at the selected location after a successful download. A cancelled or incomplete download aborts its writer.

The seekable reader finds the ZIP central directory in the archive tail. It reads central metadata and selected file content from 32 KiB Blob slices, supports ZIP64 offsets and entries, STORE and DEFLATE, and validates entry length and CRC32 before analysis. It rejects unsafe names, encrypted entries, unsupported compression, out-of-bounds offsets and invalid central directories. The previous JSZip path is retained only for archives at most 64 MiB on browsers without `deflate-raw` streams.

For archives beyond the core pass, UCE now indexes **all eligible paths** and reads the remaining source text in batches of at most 128 files / 8 MiB of text. It runs independent per-file security and browser checks over the newly read content. It also computes the language inventory from the complete eligible file list. Local OPFS checkpoints record the report and next entry approximately every 1,024 files; restarting the same ZIP resumes from the last checkpoint after the archive identity and full index metadata agree. A cancelled private GitHub download is retained for in-session resume and removed after successful completion or reset. Browsers without OPFS repeat the batch pass from the beginning.

The report separates eligible paths indexed, readable text actually read, security/browser source files checked, and the **core rules input**. A complete ZIP index or 100% eligible source-text read does **not** mean 100% rule coverage. Architecture and cross-file checks, V3 rules with their own budgets, oversized source files and capped finding lists can still be partial; UCE labels the overall assessment partial in those cases. An aborted batch scan does not produce a final report. Batch metadata and findings, not the whole extracted source tree, stay resident at once.

Limits remain explicit: compressed ZIP <= 2 GiB, central directory <= 512 MiB and <= 1,000,000 entries, analyzable uncompressed total <= 5 GiB, initial cross-file analysis of at most 25,000 files / 96 MiB of source text, 2 MiB per text file, and 300 security / 200 browser findings retained. ZIP indexing still requires the full download first. File picker support varies by browser; private storage and the bounded memory path remain available.

Run `npm run benchmark:zip-batches` to verify the ZIP64, 96,000-file batch path with bounded-memory synthetic data. This is a structural stress test, not evidence that every rule has checked every file in a real Linux revision. For source trees beyond the ZIP safety ceiling or complete project-wide rule analysis, use the CLI with explicitly raised budgets or analyze smaller subtrees; the CLI's default budget is also 25,000 files / 96 MiB.
